## ✨ Возможности

- **Три метода**: Гаусс, уточнение решения по невязкам, Гаусс-Зейдель.
- **Система из файла**: матрица читается из `matrix.txt`, размер системы определяется автоматически.
- **Пошаговый вывод**: каждое преобразование матрицы, каждая итерация, формулы с подставленными числами. Всё в панелях с цветным оформлением (библиотека Rich).
- **Округление по правилу 5** (half up), как при вычислениях вручную, а не банковское округление встроенного `round`.
- **Автоматическая подготовка к методу Зейделя**: программа проверяет достаточное условие сходимости (диагональное преобладание) и, если оно не выполнено, подбирает элементарные преобразования строк, после которых оно выполняется.
- **Сравнительная таблица**: корни всех методов рядом с точным решением, максимальная погрешность каждого метода. Корни, совпавшие с точными, подсвечиваются.
- **Точное решение без ошибок округления**: считается в обыкновенных дробях (`fractions.Fraction`) по десятичной записи чисел из файла.

## 📐 Методы

| Метод | Идея | Условие остановки |
|---|---|---|
| **Гаусса** | прямой ход приводит матрицу к треугольному виду, обратный ход находит корни | — (прямой метод) |
| **Уточнения** | по приближению `x⁽ᵏ⁾` считаются невязки, из СЛУ для поправок (решается Гауссом) находится `ε⁽ᵏ⁾`, приближение исправляется | все `\|εᵢ\| < ε` |
| **Гаусса-Зейделя** | каждое `xᵢ` выражается из своего уравнения, новые значения используются сразу | все `\|rᵢ\| < ε` |

### Формулы

**Гаусс.** Прямой ход: для строки `k` под ведущей строкой `i`

$$c = \frac{a_{ki}}{a_{ii}}, \qquad a_{kj} := a_{kj} - c\,a_{ij}, \quad j = i+1, \dots, n+1$$

Если ведущий элемент равен нулю, строка меняется местами с нижней, где элемент отличен от нуля. Обратный ход:

$$x_i = \frac{1}{a_{ii}}\left(b_i - \sum_{j=i+1}^{n} a_{ij}\,x_j\right)$$

**Уточнение решения.** Для приближения `x⁽ᵏ⁾`:

```math
b_i^{(k)} = \sum_{j=1}^{n} a_{ij}\,x_j^{(k)}, \qquad
r_i^{(k)} = b_i - b_i^{(k)}, \qquad
A\,\varepsilon^{(k)} = r^{(k)}, \qquad
x^{(k+1)} = x^{(k)} + \varepsilon^{(k)}
```

Начальное приближение берётся из метода Гаусса. Число знаков в вычислениях: `⌈−lg ε⌉ + 1`, итоговый ответ округляется до `⌈−lg ε⌉` знаков.

**Гаусс-Зейдель.** Из `i`-го уравнения выражается `xᵢ`, при этом для `j < i` берутся уже новые значения `x⁽ᵏ⁾`, а для `j > i` значения предыдущей итерации:

$$x_i^{(k)} = \frac{1}{a_{ii}}\left(b_i - \sum_{j<i} a_{ij}\,x_j^{(k)} - \sum_{j>i} a_{ij}\,x_j^{(k-1)}\right)$$

Затем приближение подставляется в левые части уравнений, считаются невязки `rᵢ = bᵢ − bᵢ⁽ᵏ⁾`. Если все `|rᵢ| < ε`, приближение считается решением с заданной точностью, иначе строится следующее. Начальное приближение: `x⁽⁰⁾ = 0`.

**Достаточное условие сходимости.** Диагональное преобладание по строкам:

$$|a_{ii}| > \sum_{j \ne i} |a_{ij}|, \qquad i = 1, \dots, n$$

### Преобразование к диагональному преобладанию

Если условие не выполнено, для каждой строки подбирается комбинация строк исходной матрицы

$$R_i' = \sum_k c_k R_k, \qquad c_k \in \{0,\ \pm 1,\ \pm 0.5,\ \pm 2,\ \pm 3\},$$

у которой диагональный элемент преобладает. Среди подходящих выбирается самая простая (меньше слагаемых, целые коэффициенты, больший запас), и проверяется, что набор новых строк линейно независим, иначе система испортилась бы. Преобразования эквивалентные, поэтому решение не меняется.

## ⌨️ Как задавать данные

### Система уравнений: `matrix.txt`

Одно уравнение на строку: коэффициенты через пробел, затем `|`, затем свободный член. Дробная часть через точку, пустые строки игнорируются.

```
0.92 -0.83  0.62 | 2.15
0.24 -0.54  0.43 | 0.62
0.73 -0.81 -0.67 | 0.88
```

Система должна быть квадратной, `n` уравнений и `n` неизвестных.

### Параметры методов

Параметры задаются в `main.py`:

| Вызов | Параметры |
|---|---|
| `Gauss(matrix, digits, show)` | `digits` знаков после запятой в вычислениях; `show` печатать ли шаги |
| `Refine(matrix, eps, x0)` | `eps` заданная точность; `x0` начальное приближение (если не задано, считается Гауссом) |
| `Seidel(matrix, eps, digits)` | `eps` точность по невязкам; `digits` знаков после запятой |
| `Compare(matrix, results, exact_digits)` | `results` список `(название, корни, знаков)`; `exact_digits` знаков в столбце точного решения |

## 🖥️ Пример работы

Система из `matrix.txt` выше, `ε = 0.0001`.

**Проверка сходимости.** Условие не выполняется ни в одной строке, поэтому для метода Зейделя матрица преобразуется:

```
R₁' = R₁ - R₂
R₂' = R₂ + R₃
R₃' = R₁ - R₃
```

```
╭──── Преобразованная матрица ────╮
│  0.68  -0.29   0.19  │  1.53    │
│  0.97  -1.35  -0.24  │   1.5    │
│  0.19  -0.02   1.29  │  1.27    │
╰─────────────────────────────────╯
```

После преобразования условие выполняется во всех строках (`0.68 > 0.48`, `1.35 > 1.21`, `1.29 > 0.21`).

**Результаты методов** (все в 5 знаках, `ε = 0.0001`):

| Метод | Итераций | x₁ | x₂ | x₃ |
|---|---|---|---|---|
| Гаусс | — | 2.22128 | 0.36705 | 0.66303 |
| Уточнение | 2 | 2.2213 | 0.3671 | 0.663 |
| Гаусс-Зейдель | 8 | 2.22143 | 0.36717 | 0.663 |
| **Точное решение** | | `2.22128` | `0.36705` | `0.66302` |

Уточнение выдаёт ответ с 4 знаками, на один меньше, чем использует в вычислениях.

Одна итерация метода Зейделя в консоли (последняя):

```
╭────────────────────────── Итерация 8 ──────────────────────────╮
│  x₁⁽⁸⁾ = 1/0.68·(1.53 - (-0.29)·0.36736 - 0.19·0.66297) = 2.22143   │
│  x₂⁽⁸⁾ = 1/(-1.35)·(1.5 - 0.97·2.22143 - (-0.24)·0.66297) = 0.36717 │
│  x₃⁽⁸⁾ = 1/1.29·(1.27 - 0.19·2.22143 - (-0.02)·0.36717) = 0.663     │
│                                                                      │
│  (2.22143, 0.36717, 0.663) - 8-е приближение                         │
│                                                                      │
│  r₁⁽⁸⁾ = b₁ - b₁⁽⁸⁾ = 1.53 - 1.53006 = -0.00006                      │
│  r₂⁽⁸⁾ = b₂ - b₂⁽⁸⁾ = 1.5 - 1.49999 = 0.00001                        │
│  r₃⁽⁸⁾ = b₃ - b₃⁽⁸⁾ = 1.27 - 1.27 = 0                                │
│                                                                      │
│  Все |r| < 0.0001, процесс остановлен                                │
╰──────────────────────────────────────────────────────────────────────╯
```

## 📊 Сравнительный анализ

Модуль `compare.py` строит таблицу: по строке на каждый корень, по столбцу на каждый метод и ещё один для точного решения. Внизу выводятся строки «Совпало» (сколько корней из `n` совпало с точными) и «Макс. погрешность».

- **Точное решение** считается методом Гаусса в обыкновенных дробях по десятичной записи чисел (`0.92` это `23/25`), поэтому ошибок округления в нём нет.
- **Совпадением** считается корень, равный точному значению, округлённому по правилу 5 до числа знаков самого метода.
- **Зелёным** подсвечены совпавшие корни и лучшая (наименьшая) максимальная погрешность. Под таблицей выводится, какой метод оказался точнее всех.

> Чтобы сравнение было честным, давайте всем методам одинаковое число знаков. Метод Гаусса с 2 знаками заведомо проиграет итерационным с 5: прямой метод накапливает ошибки округления, а итерационные исправляют их на каждом шаге.

```
.
├── main.py               # чтение matrix.txt, запуск методов и сравнения
├── matrix.txt            # расширенная матрица системы
├── utils.py              # округление, форматирование чисел и формул, панели вывода

├── requirements.txt      # зависимости
└── methods/
    ├── gauss.py          # метод Гаусса
    ├── refine.py         # уточнение решения по невязкам
    ├── seidel.py         # метод Гаусса-Зейделя
    └── dominance.py      # проверка диагонального преобладания и преобразование матрицы
```

Общие вспомогательные функции вынесены в `utils.py`: `fmt` (число без лишних нулей), `par` (отрицательные числа в скобках), `lin` (линейная комбинация для вывода формул), `sub` и `sup` (нижние и верхние индексы), `banner` и `error` (плашки с названием метода и ошибкой), `rnd` (округление по правилу 5).

## ⚠️ Ограничения

- Условие остановки по невязкам `|rᵢ| < ε` не гарантирует, что погрешность корней не превышает `ε`. Точность по самим корням зависит от обусловленности матрицы: на плохо обусловленных системах невязки малы, а корни остаются неточными.
- Метод Гаусса меняет строки местами только при нулевом ведущем элементе (выбора главного элемента нет), поэтому при малом числе знаков ошибки округления могут быть заметными.
- Достаточное условие сходимости не необходимое: метод Зейделя может сойтись и без него. Если подобрать преобразования не удалось, Зейдель всё равно запускается по исходной системе с предупреждением и может расходиться. Расходимость определяется по росту значений (`> 10¹²`).
- Подбор преобразований перебирает комбинации с коэффициентами из фиксированного набора, число вариантов растёт как `9ⁿ`, поэтому метод рассчитан на небольшие системы (до 5–6 уравнений).
- Число итераций ограничено 50. Если точность не достигнута, программа сообщает об этом и выводит последнее приближение.
- Поддерживаются только системы с единственным решением. Для вырожденных систем программа выводит сообщение об ошибке.
